## 0. 立场

看板页好看，一半是设计，一半是它本来没那么多东西要放。
业务系统 UI 差，多数时候不是设计师不行，是"一屏要塞 12 个筛选 + 8 种状态 + 3 个操作按钮"这个约束本身不美。

所以本文档的目标不是"照着看板重做后台"，而是——
**借设计系统和展示层规范（可迁移），不借低密度布局（不可迁移）。**

判断一条能不能借，只问一个问题：

> 这条改完之后，用户完成一次高频任务是多点了几下，还是少点了几下？
> 少点或持平 → 可借。多点 → 不可借，无论它多好看。

## 1. 可借的 6 条

> 每条都带 **验收口**——"怎么算做完"。没有验收口的条目不允许进入开发。
> 每条都标明 **落地阶段**——不在当前阶段范围内的条目，验收口不生效。

### 1.1 布局骨架：顶部指标卡 → 中部趋势 → 底部明细

> **落地阶段：P3 后续**（`/dashboard` 重排已标暂缓，本轮不动）

- **借什么**：页面的纵向叙事结构，用于驾驶舱 / 工作台这类"看全局"的页。
- **不借什么**：把订单、商品这类"逐行干活"的页面也改成三段式。
- **现状（已实测）**：`/ops` 运营工作台的锚点为「商品资料 → 基础资料 → 创建预计入库 → 运营确认入账 → 当前库存 → 补货与采购」，是**流程向导式**结构，不是表格堆叠；`/dashboard` 运营驾驶舱已有 5 个面板（销量趋势 / 库存风险 / 商品表现四象限 / 数据同步健康 / SKU 库存健康）+ 异常收件箱 + 指标口径。**v1 中"一进来就是一张大表格"是推测，实测不成立，已撤回。**
  - 真正待验证的只剩一件事：`/dashboard` 首屏是否需要重排为「指标卡 → 趋势 → 明细」。这属于重构，不是新增，归 P3 后续。
- **前置条件**：本条的方案设计与 P3 第一轮**无交集**，第一轮不得触碰任何页面布局。
- **验收口**：结构方案定稿（静态稿或标注截图即可），且不新增页面、不改动任何接口返回结构。

### 1.2 指标卡规范

> **落地阶段：P3 第一轮**（仅 `/ops` 首屏）

四件套，与业务逻辑无关，纯展示层：

| 元素 | 规范要点 |
|---|---|
| 主数字 | 大字号（正文 2.5–3 倍），数字等宽，避免刷新时跳动 |
| 标签 | 小字号 + 中性色，一个指标只表达一件事 |
| 变化值 | 环比/同比箭头 + 百分比；**箭头方向与颜色解耦**（颜色口径见 1.6，未确认前不上色） |
| 辅助信息 | 必须写明口径来源，否则数字会被误读 |

**两条硬约束：**

1. **口径必须可追。** 每个指标卡要能点开口径说明，且与后台报表/接口抽同一个指标对账一致。
2. **无数据源不得上首屏。** 上线前须确认该指标的数据源真实存在且口径可追；不满足的，一律不上首屏，只在文档中登记为「依赖 P3+ / 当前不可实现」。

**已知需带入 P3 判定的两个具体项（来自前序评审）：**

| 指标 | 数据源状态 | 处置 |
|---|---|---|
| GMV | 订单聚合（外部订单事实表），**非手填** | 可上，但需在口径说明中标明"外部平台订单聚合、只读、不等于内部履约收入" |
| 达人合作漏斗 | **当前无数据源** | 本期不上首屏，登记为「依赖 P3+ / 不可实现」 |

**验收口**：`/ops` 首屏指标卡全部上线且 ≤ 6 张；每张可点开口径说明；随机抽 1 个指标与后台报表对账一致；无数据源指标数为 0。

### 1.3 图表规范

> **落地阶段：P3 后续逐页**（第一轮不动图表）

5 条规则：

1. **一个图表库**，全站不混用（当前用 ECharts，保持）。
2. **一套配色**，按语义分色（正向 / 负向 / 中性 / 预警），不按顺序堆色板。
3. **坐标轴规则固定**：数值轴从 0 起、标单位、时间轴格式统一、网格线弱化到刚好可读。
4. **空态有设计**：无数据给灰态占位 + 一句说明，不留白框。
5. **单页图表数量上限：初始建议 ≤ 4**（**待验证**：`/dashboard` 现有 5 个面板，硬上限需按实际页面调整，不作为验收硬指标）。

**验收口**：抽查 2 个含图表的页面，图表库唯一、语义色取值来自 token、坐标轴 3 项规则全部符合、空数据时非白框。

### 1.4 空状态与加载态

> **落地阶段：P3 第一轮**（规范 5 场景 + 1 处示范实现）

| 场景 | 现状（实测） | 应该的样子 |
|---|---|---|
| 列表无数据 | **已有较好实践**，如订单页"暂无订单事实；没有数据不代表接口失败"、客服页"暂无匹配结果"——带解释、不只一行字 | 保留并统一为同一组件 |
| 筛选后无结果 | 部分页面未区分"无数据"与"无匹配" | 明确"按当前筛选无结果" + 一键清除筛选 |
| 首次加载 | 多为纯文本"正在加载…"，无骨架 | 骨架屏，保持行列结构，避免布局跳动 |
| 局部刷新 | 部分整块替换 | 局部 loading，不遮挡可操作区域 |
| 出错 | 客服、订单页已有中文错误 + 重试入口 | 统一为同一组件，禁止英文/裸报错 |

> 结论：空态不是"从零补"，而是**把已有的分散文案收敛成一个组件**，成本低于 v1 估计。

**验收口**：上表 5 个场景在设计规范中各有一条定义；在 1 个页面做出示范实现并截图留档；该页 5 个场景均可复现。

### 1.5 设计 token

> **落地阶段：P3 第一轮**（收敛内联 `<style>`，不逐页改样式）

最小集合：

```
颜色  primary / primary-hover / neutral-0..900 / success / warning / danger / info
      bg / surface / border / text-primary / text-secondary / text-disabled
字号  12 / 13 / 14 / 16 / 20 / 24 / 32   （阶梯不超过 7 级）
行高  紧凑 1.4（表格） / 常规 1.6（正文）
间距  4 的倍数：4 / 8 / 12 / 16 / 24 / 32
圆角  小 4 / 中 8 / 大 12
阴影  仅 2 级（卡片 / 浮层）
```

- **硬约束**：主色只用于「主按钮 / 选中态 / 链接」三处，不做大色块背景。
- **不含涨跌色**：token 首版**不定义**涨跌色，见 §1.6 与 §7 第 1 项。
- **现状（已实测）**：各模板自带 `<style>` 内联变量，色值已基本一致（`--brand:#2a78d6`、`--ink:#142033`、`--line:#e4eaf2`、`--good/warning/critical`），**已有事实上的 token，缺的是收敛到一处**。
- **成本（待页面清单填完后重新评估）**：v1 写的"中"是经验值。现实际模板 8 个，合计约 15.9 万字符，若只为合并内联 `<style>` 到一份 token 文件，成本为**低**；若后续新增页面增多需追溯替换，再上调。

**验收口**：token 文件落库且唯一来源；任意页面不出现硬编码色值（抽查 3 个文件，允许保留兼容别名并标注）。

### 1.6 表格可读性

> **落地阶段：P3 第一轮后逐页**（订单页优先）

- **行高**：紧凑 36–40px，不为"呼吸感"拉到 56px（直接减少一屏行数）。
- **斑马纹**：极浅底，不描重边框。
- **数字右对齐 + 等宽数字**，金额固定两位小数；文本左对齐；状态居中。
- **状态用 badge**，不用纯文字。
- **颜色语义先定死**：涨/跌、成功/失败、正向/负向各用哪个色，全站一致，写进 token，之后不再讨论。

> ⚠️ **涨跌色的方向：待确认，本文档不设默认值。**
> 系统实际用户群未确认。若面向海外/跨境，绿涨红跌与国内习惯相反，写错会导致全站语义反向。
> **落地前必须回答两个问题**：（1）系统面向谁？（2）团队有无既有约定？
> 确认后写入 token 文件并注明「已确认 / 日期 / 依据」。
> **未确认前，token 中不定义涨跌色**，表格只用 success / warning / danger 表达状态，不用颜色表达涨跌。
> **超期规则**：若 P3 启动时仍未确认，则本期**永久不定义**涨跌色，表格始终不用颜色表达涨跌；后续有人拍板再单独补，不因"顺手"带进 token 定义。
>
> 现状备注（实测）：订单页已有 badge（`.tag / .warn / .good`），但表格数字未右对齐、未等宽。这一条是"补齐"，不是"重做"。

**验收口**：抽查 3 个列表页，数字右对齐 + 等宽 + 金额两位小数 + 状态 badge 四项全部符合；涨跌色在 token 中已标注确认状态（或按超期规则标注"本期不定义"）。

## 2. 不可借的 4 条

| # | 不可借 | 为什么 | 典型误用 |
|---|---|---|---|
| 1 | **大卡片大留白** | 一屏要放更多行，留白=要滚动=操作变慢 | 把订单列表改成每单一张大卡片 |
| 2 | **图表替代明细** | 看板只要"看懂"，业务系统要"改动" | 订单页只给趋势图，没法逐行改状态 |
| 3 | **隐藏筛选器** | 看板筛选是低频探索，业务系统筛选是高频动作 | 把 6 个筛选项收进"更多筛选"，每次多点两下（订单页当前 6 个筛选常驻，保持） |
| 4 | **过度动效** | 看板动效是装饰，业务系统动效拖慢批量 | 列表增删都做 200ms 动画，批量 50 条时变卡顿 |

补充判断标准：**任何"让单屏信息量下降"的改动，默认归入不可借**，除非有数据证明该页不是高频页。

## 4. 落地节奏与入口条件

### 现在（执行线 = P1 残留三件）

- ✅ 只做一件事：修订并归档本文档。
